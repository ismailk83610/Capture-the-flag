
# Information Gain for Frontier-Based Exploration

## 1. Introduction

Information Gain (IG) is a concept used in autonomous exploration to measure how much new information an agent expects to obtain by observing an unexplored area.

In our flag-capture project, the agent must explore an initially unknown environment, identify opponent flags, collect them, and return to its home base.

The agent should explore efficiently rather than move randomly.

We have selected the following preliminary approach:

**Frontier Exploration + Information Gain per Distance + A* Pathfinding**

Each component serves a different purpose:

| Component | Purpose |
|---|---|
| Frontier Exploration | Identifies potential exploration destinations |
| Information Gain | Estimates how many new cells could be discovered |
| IG per Distance | Ranks frontier destinations based on exploration benefit and travel cost |
| A* Pathfinding | Calculates routes through known traversable cells |
| Dynamic Map Storage | Maintains and updates the agent's internal map |

Information Gain is used during the exploration phase to help the agent choose which frontier to visit next.

---

## 2. Why Do We Need Information Gain?

Consider an agent exploring an unknown map.

After moving through several locations, it has discovered multiple frontier cells.

A frontier is a known, reachable cell that is adjacent to at least one unknown cell.

Suppose the agent has three possible destinations:

- Frontier A could reveal 4 unknown cells.
- Frontier B could reveal 10 unknown cells.
- Frontier C could reveal 6 unknown cells.

The agent must decide where to explore next.

Without an exploration-selection strategy, the agent might:

1. Randomly select a frontier.
2. Always choose the nearest frontier.
3. Repeatedly travel between different regions.
4. Spend too many steps exploring low-value areas.

Information Gain helps the agent prioritize frontiers that are expected to reveal useful new areas.

**Main objective: Discover more of the unknown environment with fewer unnecessary movements.**

This can support the project's ultimate goal of locating opponent flags efficiently.

However, discovering map cells and discovering flags are not exactly the same objective. The effectiveness of Information Gain for flag discovery must be tested.

---

## 3. What Is Information Gain?

Information Gain measures the expected amount of new information obtained by exploring a particular location.

In our initial implementation, we use a simple interpretation:

**Information Gain = Expected number of previously unknown cells that become known.**

For example:

If moving toward Frontier A is expected to reveal 5 unknown cells:

IG(A) = 5

If moving toward Frontier B is expected to reveal 9 unknown cells:

IG(B) = 9

Frontier B has higher Information Gain.

However, Information Gain alone does not consider the distance required to reach the frontier.

Therefore, we later combine Information Gain with travel cost.

### Important distinction

Information Gain is an estimate made before the agent moves.

The actual number of new cells discovered may be different.

For example:

Expected Information Gain = 8 cells

Actual newly discovered cells = 5 cells

This can happen because:

- Walls obstruct visibility.
- Some cells are outside the actual observation region.
- The agent observes certain cells before reaching the target.
- The map changes while the agent is moving.

The real observation behavior must be determined from the project API.

## 5. Calculating Information Gain

### 5.1 Basic counting method

Our preliminary method counts expected newly observable unknown cells.

The formula is:

$$
IG(f) = \sum_{c \in V(f)} I(c)
$$

Where:

- \(f\) = Candidate frontier.
- \(V(f)\) = Cells expected to become observable from that frontier.
- \(c\) = A cell in the observation region.
- \(I(c)\) = Indicator function.

The indicator function is:

$$
I(c)=
\begin{cases}
1 & \text{if cell }c\text{ is currently unknown}\\
0 & \text{if cell }c\text{ is already known}
\end{cases}
$$

### 5.2 Example calculation

Suppose Frontier A could reveal the following cells:

```text
Cell 1 = Unknown
Cell 2 = Unknown
Cell 3 = Known
Cell 4 = Unknown
Cell 5 = Known
Cell 6 = Unknown
```

The calculation becomes:

```text
IG(A) = 1 + 1 + 0 + 1 + 0 + 1

IG(A) = 4
```

Therefore:

**Expected Information Gain of Frontier A = 4 new cells.**

### 5.3 Estimating visibility

The simplest initial estimator can count unknown cells within a potential observation window around a frontier.

For a 5×5 window:

```text
Radius = 2 cells in each direction
```

The candidate position is at the center:

```text
x x x x x
x x x x x
x x F x x
x x x x x
x x x x x
```

Here, each `x` represents a position in the potential observation window.

The agent must compare these positions against its stored map.

It should count only unknown cells expected to become visible.

### Assumption requiring verification

The actual API may apply:

- Wall-based visibility restrictions.
- Map boundary restrictions.
- Special observation rules.
- Different visibility behavior for different cell types.

Therefore, the final estimator must match the real API behavior.

A rectangular 5×5 count is only an initial approximation until visibility rules are verified.

## 6. Why Information Gain Alone Is Not Enough

Imagine three candidate frontiers:

| Frontier | Information Gain | Distance |
|---|---:|---:|
| A | 4 | 2 |
| B | 10 | 8 |
| C | 6 | 3 |

If the agent chooses only the highest Information Gain:

```text
Frontier B = 10 new cells
```

It will travel 8 steps to reach Frontier B.

However, Frontier C can reveal 6 cells after only 3 steps.

Therefore, selecting the highest Information Gain does not necessarily produce efficient exploration.

We must consider both:

1. Expected new information.
2. Cost of travelling to the frontier.

This motivates Information Gain per Distance.

## 7. Information Gain per Distance

### 7.1 Selected scoring function

For our initial implementation, we selected:

$$
\boxed{Score(f)=\frac{IG(f)}{d(f)+1}}
$$

Where:

- \(Score(f)\) = Score of frontier \(f\).
- \(IG(f)\) = Expected Information Gain of that frontier.
- \(d(f)\) = Shortest traversable path distance from the agent to the frontier.

The distance is calculated using the known map.

We plan to use A* pathfinding to calculate the route.

### 7.2 Why divide by distance?

The goal is to balance the amount of new information and the cost of obtaining it.

A frontier with:

- High Information Gain
- Low travel distance

will usually receive a high score.

A frontier with:

- Low Information Gain
- High travel distance

will usually receive a low score.

### 7.3 Why add 1?

The formula contains:

```text
Distance + 1
```

This prevents division by zero when the agent is already at the frontier.

Example:

```text
Distance = 0
Information Gain = 5
```

Without adding 1:

```text
Score = 5 / 0
```

This is undefined.

With the selected formula:

```text
Score = 5 / (0 + 1)
Score = 5
```

This also slightly changes the relative scores of short-distance destinations.

Therefore, the exact scoring formula is a design choice rather than a universal rule.

Consider these three frontiers:

|---|---:|---:|
| A | 4 | 2 |

### Frontier A

$$
Score(A)=\frac{4}{2+1}

$$

### Frontier B

$$

$$
Score(B)=1.11
$$

### Frontier C

$$

$$

### Final comparison

| Frontier | Score | Ranking |
|---|---:|---|
| A | 1.33 | 2 |
| B | 1.11 | 3 |
| C | 1.50 | 1 |

The agent chooses:

**Frontier C**

Reason:

Frontier C provides the highest expected information benefit relative to travel distance under our selected scoring rule.

Notice that Frontier B reveals the most cells, but it is comparatively far away.

Frontier C offers a better balance.

## 9. Alternative Frontier Scoring Methods

Different frontier-selection methods exist.

We considered four possible approaches.

### 9.1 Maximum Information Gain

Formula:

$$
Score(f)=IG(f)
$$

The agent chooses the frontier expected to reveal the most unknown cells.

Advantages:

- Very simple.
- Prioritizes larger unexplored regions.
- Does not require travel-cost estimation for scoring.

Limitations:

- Ignores travel distance.
- May produce unnecessarily long journeys.
- May be inefficient when many distant frontiers exist.

### 9.2 Information Gain minus Travel Cost

Formula:

$$
Score(f)=IG(f)-\lambda d(f)
$$

Where:

- \(\lambda\) = Adjustable distance penalty.
- \(d(f)\) = Travel distance.

Example:

```text
IG = 8
Distance = 3
Lambda = 1
```

Calculation:

```text
Score = 8 - (1 × 3)
Score = 5
```

If lambda increases, longer journeys are penalized more heavily.

Advantages:

- Considers both information and distance.
- Flexible scoring behavior.

Limitations:

- Requires parameter tuning.
- An unsuitable lambda can overly prioritize either distance or information.

### 9.3 Information Gain per Distance

Formula:

$$
Score(f)=\frac{IG(f)}{d(f)+1}
$$

Advantages:

- Simple calculation.
- Considers both information and travel distance.
- Does not require an explicit weighting parameter.
- Suitable for a preliminary C++ implementation.
- Easy to compare experimentally against baseline methods.

Limitations:

- May prioritize several nearby, low-gain destinations.
- May delay exploring distant regions.
- Depends on accurate gain and distance estimates.
- Does not directly estimate the probability of finding a flag.

**Decision: Selected for our preliminary implementation.**

### 9.4 Weighted Utility Function

Formula:

$$
Score(f)=w_g IG(f)-w_d d(f)-w_r R(f)
$$

Where:

- \(w_g\) = Information Gain weight.
- \(w_d\) = Travel-distance weight.
- \(w_r\) = Risk weight.
- \(R(f)\) = Estimated risk associated with the frontier.

This method could be extended to consider:

- Enemy positions.
- Trap locations.
- Dangerous regions.
- Other strategic costs.

Advantages:

- Flexible.
- Can account for multiple objectives.
- May be useful for competitive environments.

Limitations:

- More complex implementation.
- Requires risk estimation.
- Requires tuning multiple weights.

**Decision: Possible future extension, not needed for the first version.**

## 10. Why We Selected Information Gain per Distance

We selected Information Gain per Distance as our preliminary exploration-scoring method for the following reasons.

### Reason 1: Exploration efficiency

Our agent should avoid wasting steps.

A distance-aware scoring method helps balance new map discovery with travelling effort.

### Reason 2: Suitable for frontier exploration

Frontier exploration produces candidate destinations.

Information Gain per Distance provides a simple way to rank those candidates.

### Reason 3: Integration with A*

A* can calculate a shortest path through known traversable cells.

The length or cost of this path can be used in our scoring function.

Therefore, A* serves two purposes:

1. Estimate the distance to each frontier.
2. Navigate toward the selected frontier.

### Reason 4: Straightforward implementation

The score requires only:

```text
Information Gain
Distance
```

Calculation:

```cpp
double score =
    static_cast<double>(informationGain) /
    (distance + 1);
```

### Reason 5: Easy evaluation

The method can be compared with simpler approaches:

- Random frontier selection.
- Nearest-frontier selection.
- Maximum-Information-Gain selection.

### Important research distinction

Our selection is a preliminary engineering decision.

The literature supports using exploration utility and travel cost, but it does not establish that our particular ratio formula is optimal for this flag-capture game.

We must evaluate it experimentally.

## 12. What Happens While Moving Toward a Frontier?

An important point is that the agent does not have to reach a frontier before discovering new cells.

Consider an agent travelling five steps toward a selected frontier.

```text
Start -> Step 1 -> Step 2 -> Step 3 -> Step 4 -> Frontier
```

At every movement, the agent may receive a new observation.

Therefore:

```text
Step 1:
    Observe environment
    Update map

Step 2:
    Observe environment
    Update map

Step 3:
    Observe environment
    Update map
```

The agent may discover previously unknown cells before reaching its selected frontier.

This means:

- Information Gain estimates can change.
- New frontiers can appear.
- Existing frontiers can disappear.
- A shorter route may become available.
- The agent may discover a flag.
- Previously known routes may become blocked.

### Replanning strategy

We initially propose:

**Update the map after each observation and re-evaluate exploration targets when necessary.**

Potential triggers include:

1. The current target becomes invalid.
2. The planned route becomes blocked.
3. A significantly better frontier is discovered.
4. The current frontier has been reached.
5. A flag or other high-priority objective is detected.

We should avoid changing targets unnecessarily after every small map update, because that could cause repeated switching between frontiers.

## 13. Entropy-Based Information Gain

### 13.1 What is entropy?

Entropy measures uncertainty.

Suppose a cell may contain either:

- A wall.
- Free space.

If the agent is completely unsure, the uncertainty is high.

If the agent knows exactly what the cell contains, the uncertainty is zero.

For a binary cell occupancy model:

$$
H(p)=-p\log_2(p)-(1-p)\log_2(1-p)
$$

Where:

- \(p\) = Probability that the cell is occupied.
- \(1-p\) = Probability that the cell is free.
- \(H(p)\) = Binary entropy.

The formula uses the convention that terms with zero probability contribute zero.

### Example

| Wall probability | Entropy |
|---|---:|
| 0% | 0 bits |
| 25% | Approximately 0.811 bits |
| 50% | 1 bit |
| 75% | Approximately 0.811 bits |
| 100% | 0 bits |

Entropy is highest when the cell is equally likely to be occupied or free.

### 13.2 Entropy-based Information Gain

A general expression is:

$$
IG=H(M)-\mathbb{E}[H(M\mid Z)]
$$

Where:

- \(H(M)\) = Uncertainty of the current map.
- \(Z\) = A possible future observation.
- \(\mathbb{E}[H(M\mid Z)]\) = Expected uncertainty after receiving the observation.

In simple terms:

**Information Gain = Uncertainty before observing − Expected uncertainty after observing.**

Example:

```text
Uncertainty before observation = 10 bits
Uncertainty after observation  = 6 bits
```

Therefore:

```text
Information Gain = 10 - 6
Information Gain = 4 bits
```

### 13.3 Do we need entropy for our project?

For our initial implementation:

**No, a full probabilistic entropy calculation is not required.**

Our preliminary map model distinguishes:

- Unknown cells.
- Known traversable cells.
- Known blocked cells.

We plan to treat observed states as definite unless the API specifies otherwise.

Under the simplified assumptions that:

1. Every unknown cell contributes one bit of uncertainty.
2. Known cells contribute zero uncertainty.
3. Newly observed cells become fully known.

The reduction in entropy is numerically equivalent to the number of newly revealed unknown cells.

Therefore, unknown-cell counting is a practical simplified Information Gain estimator.

### Decision

- Study entropy as theoretical background.
- Do not implement probabilistic entropy in the first version.
- Implement unknown-cell counting.
- Reconsider entropy if uncertain or noisy observations are introduced.

## 15. Integration with the Flag-Capture Strategy

Our project is not simply a map-exploration task.

The agent must search for flags, collect them, and return them to its home location.

Therefore, Information Gain should be part of the broader agent decision system.

### State 1: Explore

The agent:

- Updates its map.
- Detects frontiers.
- Estimates Information Gain.
- Calculates distance-aware frontier scores.
- Chooses an exploration destination.
- Navigates using A*.

### State 2: Approach flag

When a target flag is detected, the agent should prioritize the flag objective.

It can use pathfinding to approach the flag.

Information Gain is no longer the main criterion for choosing its destination.

### State 3: Collect flag

The agent performs the required flag-collection action when permitted by the API.

### State 4: Return home

After collecting a flag, the agent uses its stored map to navigate toward its home base.

A* can calculate a suitable return route.

If the environment changes, the agent updates its map and replans.

### State 5: Resume exploration

Depending on the game rules and remaining objectives, the agent may resume exploration after completing the flag delivery.

### Relationship to the Finite State Machine

```text
EXPLORE
   |
   | Flag discovered
   v
APPROACH_FLAG
   |
   | Flag reached
   v
COLLECT_FLAG
   |
   | Flag collected
   v
RETURN_HOME
   |
   | Home reached
   v
DELIVER_FLAG
   |
   | Continue searching if required
   v
EXPLORE
```

This is a proposed behavioral model. Exact transitions must follow the API and game rules.

## 17. Limitations and Risks

### 17.1 Information Gain is only an estimate

The agent may reveal fewer cells than expected.

### 17.2 Walls may restrict observations

Counting every unknown cell in a square can overestimate information if visibility is obstructed.

### 17.3 Short-distance bias

Information Gain per Distance may repeatedly prefer small nearby areas over larger distant areas.

### 17.4 No direct flag probability

Unknown-cell counting measures potential map discovery.

It does not explicitly predict where opponent flags are located.

### 17.5 Dynamic obstacles

Map changes may invalidate previously calculated distances or routes.

### 17.6 Target switching

Frequent recalculation may cause the agent to repeatedly switch between frontier targets.

### 17.7 Exploration may not equal game performance

Higher map coverage does not automatically mean:

- Faster flag discovery.
- Faster flag delivery.
- Greater number of captured flags.
- Better overall game performance.

Therefore, game-specific evaluation is essential.

## 21. Final Decision

After reviewing the concepts and preliminary literature, our selected approach is:

**Frontier-Based Exploration with Unknown-Cell Information Gain and Distance-Normalized Frontier Scoring.**

Our initial scoring function is:

$$
\boxed{Score(f)=\frac{IG(f)}{d(f)+1}}
$$

We selected this approach because:

1. It is conceptually simple.
2. It considers both information benefit and travel distance.
3. It can integrate with A* pathfinding.
4. It fits our initial known/unknown map representation.
5. It can be implemented in C++ without a probabilistic mapping framework.
6. Its performance can be measured against alternative frontier-selection methods.

### What is supported by literature?

- Frontier-based exploration is an established approach for exploring unknown environments.
- Information Gain is a useful concept for evaluating exploration benefit.
- Combining exploration utility with travel cost is supported by prior robotics research.

### What still needs experimental verification?

- Whether IG per Distance outperforms nearest-frontier selection in our game.
- Whether the 5×5 observation allows accurate Information Gain estimation.
- Whether the heuristic reduces steps to flag discovery.
- Whether frequent replanning improves or reduces performance.
- How dynamic obstacles affect exploration decisions.

### Final conclusion

Information Gain helps our agent make informed exploration decisions instead of selecting frontiers randomly.

By combining expected map discovery with A* path distance, we aim to achieve efficient exploration while searching for opponent flags.

Entropy-based Information Gain is important theoretical background, but is not required for our initial implementation under the assumption of reliable discrete cell observations.

**Our next development task is to implement and test unknown-cell Information Gain estimation using the actual observation rules provided by the game's API.**
